# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Codebase Overview

Monorepo of Grupo Escoteiro Albert Schweitzer: a public static site and an internal management app (Financeiro + Inventário + Associados) on PostgreSQL (Azure in production), sharing a UI package.

**Stack**: Astro 7 + Tailwind v4 (site); Next.js 16 App Router + Server Actions, PostgreSQL 17 via the `postgres` driver (RLS, audited SQL functions), Google login (OIDC) with own sessions, Azure Blob Storage, shadcn/ui on Base UI (internal app); Vitest, pgTAP, Playwright.
**Structure**: `apps/institucional`, `apps/gestao` (`app/` routes, `components/`, `lib/{finance,inventory,associates,server}`, `db/`), `packages/ui`.

For detailed architecture (route table, data layer, migrations, data flows, gotchas), see [docs/CODEBASE_MAP.md](docs/CODEBASE_MAP.md).

## Monorepo

npm workspaces (`apps/*`, `packages/*`) with a single root `package-lock.json`. Always run `npm install` from the root, never inside an app.

- `apps/institucional` (`@geas/institucional`) — public static site, Astro 7 + Tailwind CSS v4, `escoteirosalbert.com.br`.
- `apps/gestao` (`@geas/gestao`) — internal app "Gestão", Next.js (App Router, Server Actions) + PostgreSQL, with one module per route prefix: Financeiro (`/financeiro/...`), Inventário (`/inventario/...`) and Associados (`/associados/...`). Needs a Node server; cannot be deployed as static files. Consolidation plan and phases: `docs/consolidacao-gestao.md`.
- `packages/ui` (`@geas/ui`) — shared UI of the internal app, consumed as TS source (no build step).

## Commands (from root)

```bash
npm run dev                 # gestao + site in one terminal (concurrently); gestao needs infra:start
npm run dev:institucional   # Astro dev server at localhost:4321
npm run dev:gestao          # Next dev server at localhost:3000
npm run build               # build all apps
npm run lint                # lint all apps
npm test                    # vitest (gestao)
npm run test:db             # pgTAP + SQL scripts (pg_prove inside the local db container)
npm run test:e2e            # Playwright, desktop Chromium, own next dev on :3210 (E2E_PORT=3000 reuses a running dev server)
npm run typecheck
npm run infra:start         # local Postgres + Azurite (Docker Compose, apps/gestao/db/compose.yaml), applies migrations, rewrites the generated block of apps/gestao/.env.local (lines below it, e.g. GOOGLE_* secrets, are kept; template apps/gestao/.env.example, guide in README "Ambiente local e segredos")
npm run db:types --workspace=@geas/gestao   # regenerate lib/server/pg/schema.ts after a migration
npm run db:migrate --workspace=@geas/gestao # apply new migrations to DATABASE_ADMIN_URL (local or Azure) without resetting
npm run db:purge --workspace=@geas/gestao   # delete associates whose 60-day quarantine ended (Azure: scheduled job)
```

Per app: `npm run <script> --workspace=@geas/<app>`.

## gestao

- Layout: `app/(gestao)` (Início `/`: what needs attention in the modules (associates: control pendencies, records expired and expiring in 30 days), the "Vencimentos de registro" card (control items with `valid_until` of active associates, expired or within 30 days: `registrationExpiries` in `lib/associates/alerts.ts`), associates birthdays and promise anniversaries (5 days back to 15 ahead; an escotista with Associados access sees dates, transitions and stars only of the youth of their sections by default, with tabs "<seção>" | "Grupo todo" (`?avisos=grupo`; `scouterSections` in `lib/associates/alerts.ts`, from the associate linked to the access); control pendencies and registration expiries stay group-wide) and branch transitions (rules in `TRANSITIONS`, `lib/associates/alerts.ts`: warning, critical and "transição iniciada" levels by age in months; late ones also counted in "Precisa de atenção"), plus one card per module, laid out as a 3/2/1-column masonry where empty lists collapse into one "Sem novidades" card and "Links úteis" (external sites, `lib/useful-links.ts`) closes the page; data from `lib/server/finance/home.ts`, `lib/server/inventory/overview.ts` and `lib/server/associates/home.ts`; header `components/shell/gestao-header.tsx`; `/rapido` (Registro rápido, below); `/login`, `/auth`, `/usuarios`) and one route group per module (`app/(financeiro)/financeiro/...`, `app/(inventario)/inventario/...`, `app/(associados)/associados/...`), each with its own root layout (`RootHtml` in `components/shell/root-layout.tsx`) that sets `<html data-app>`; crossing modules is a full page load. Unknown URLs: `app/global-not-found.tsx`. Pre-consolidation finance URLs (`/lancamentos/...` etc.) redirect in `next.config.ts`.
- Code per module: pure domain in `lib/finance/`, `lib/inventory/` and `lib/associates/`, components in `components/finance/`, `components/inventory/` and `components/associates/`; shared at the root (`lib/money.ts` (`parseMoneyToCents` reads `1.234,56`, `R$`; `allowNegative`), `lib/format.ts` (`money` takes reais, `formatCents` cents), `lib/auth.ts`, `lib/action.ts`, `components/shell/`).
- **Data layer (`lib/server/`)**: the only code that talks to the database. Only `lib/server/**` imports `postgres` and `@azure/*`, and only `lib/server/pg/**` builds the connection (ESLint `no-restricted-imports`, error in the whole app; off only in `lib/server/**`, `e2e/**`, `scripts/**`). Screens and actions call use-case functions in `lib/server/<module>/*.ts` (`lib/server/finance/{registry,associates,entries,attachments,reconciliation,statements,fees,debts,reports,home}.ts`, `lib/server/inventory/{locations,families,materials,movements,overview}.ts`, `lib/server/associates/{associates,sections,functions,relatives,controls}.ts`, `lib/server/users.ts`; storage in `lib/server/files.ts`) with `member.db` (opaque `Db`, RLS as the user); never build queries in pages. Data modules take typed input, return domain types (`lib/inventory/model.ts`, row types such as `lib/finance/entry-rows.ts`; client components import types/constants from `lib/finance` or `lib/inventory`, never values from `lib/server`), throw `DataError`, and don't import `next/*`. Validation (`InputError`), `revalidatePath` and `redirect` stay in the action; `runAction(guard, work)` in `lib/action.ts` turns errors into `ActionResult`. Reads are SQL with bound parameters through `rows`/`one`/`count`/`run` from `lib/server/pg/db.ts` (each call is a short transaction that sets role `authenticated` and `request.jwt.claims`, so RLS and `auth.uid()` apply); writes are the audited SQL functions via `rpc()` (named arguments, names and types checked against `lib/server/pg/schema.ts`, generated by `scripts/db-types.mjs`; the function catalog is cached per process and re-read once when a signature does not match, so `db:migrate` works with the dev server running). No key bypasses RLS: users and roles go through the audited functions `group_users`, `admin_add_member`, `admin_remove_member`; `ownerDb()` (connection role) only in scripts. Auth (Google login, sessions, sign-out) only through `lib/server/auth.ts`; `proxy.ts` only checks that the session cookie exists and renews its max-age on document GETs (never queries).
- Importação por CSV (`/importar`, 006): one screen for every module (Editor of Associados or Inventário; each file needs its module's editor), reached from the account menu's "Administração" group (with Usuários; `adminLinks` in `components/shell/account-menu.tsx`), never from a module's Configurações. The contract is `apps/gestao/docs/importacao.md`, written for whoever (or whichever AI) converts the group's spreadsheets; its column tables are generated from `lib/import/contract.ts` (single source: reading, templates, exports; `npm run import:doc --workspace=@geas/gestao`, a test checks they match). Pure code in `lib/import/` (`read.ts` file → typed rows, `plan.ts` preview against the current state (`lib/server/import.ts`) and the other files of the same upload, `export.ts` current data in the same format: exporting and reimporting gives everything "igual"). The action reads and plans again on the server and sends only new/changed rows to `import_batch` (one transaction; per-file SQL functions reuse the audited ones; errors carry file and line). Empty cell = no change; people are matched by `id`, else name + birth, else a unique name; missing sections/patrols are created and listed in the preview. Every file of the contract is available (`secoes`, `itens-controle`, `pessoas`, `funcoes`, `responsaveis`, `controle`, `vida-escoteira`, `inventario-lotes`, `inventario-pecas`; migrations 006–010; `lancamentos` (013; Financeiro Administrador only, 015): one split per row, `lançamento` column groups rows into one entry, sign from the category kind, category by code, missing accounts/payment methods created, unknown associate → warning + name in notes, identified by `id` or date + account + histórico + total counted one by one; only creates, never updates; converter `npm run finance:csv` (`scripts/finance/planilha-para-csv.ts`)), each with "Dados atuais" export in the same format. `vida-escoteira` replaces, per person, each kind of fact present; the inventory files replace the whole inventory. Converters from the group's spreadsheets (output checked with the same read + plan, exit 1 on any row error): `npm run associates:csv --workspace=@geas/gestao -- <dir with Docs 10/13/14/22 .xlsx> <out>` (`scripts/associates/planilhas-para-csv.ts`; summary shows only counts and sheet positions, names only with `--detalhes`) and `inventory:csv` (below).
- Registro rápido (`/rapido`, 049): phone screens shared by the modules. Top: one search (`q`) for materials (inventory contributors: opens the material's quick actions) and active associates by name/nickname (associates readers: opens the profile; `search` in `lib/server/associates/associates.ts`). "Registrar" lists, per module's contributors (Colaborador or more): lançamento financeiro (`/rapido/lancamento`: only Receita or Despesa, no rubrica: the server books it on root `1` Receitas / `2` Despesas by the sign (`rootCategory`) and the reviewer classifies, account = payment method default or "A definir", optional receipt upload after saving when attachments are on; `create_quick_ledger_entry`), associado novo (`/rapido/associado`: `AssociateForm quick`; `associates_create_quick`) and material novo (`/rapido/inventario/novo`); inventory actions at `/rapido/inventario/[id]?acao=…` (`inventory_quick`). Actions in `app/(gestao)/rapido/actions.ts`; confirmation `?feito=<tipo>&id=` (`lib/quick.ts`). Everything enters for real and stays "para revisar" (`review_status` on `ledger_entries` and `associates`, inventory movements as before; the same for anything a Colaborador writes in the normal screens); each module reviews in its own list: Financeiro `?revisao=para_revisar` pill + "Revisar" mark + bulk "Marcar revisados" + notice on the entry (`review_ledger_entries`), Associados `/associados?revisao=para_revisar` + notice on the profile (`associates_review`), Inventário Movimentações › Para revisar. Início counts them. Old `/inventario/rapido/*` URLs redirect.
- Roles (003, `docs/plano-go-live.md` §1): the same five levels in every module, enum `module_role` in `memberships.finance_role` / `inventory_role` / `associates_role`, ordered `none` (Sem acesso: module hidden, RLS blocks reading) < `viewer` (Consulta) < `contributor` (Colaborador: day-to-day work, i.e. entries, associates (functions, moves, control statuses, relatives) and materials/movements, and whatever they write is set `para_revisar` by triggers) < `editor` (Editor: also reviews, settings, imports, reconciliation, fees) < `admin` (Administrador: also manages that module's users). Labels/help in `@geas/ui/lib/roles` (`MODULE_ROLES`, `MODULE_ROLE_LABELS`, `roleAtLeast`). No group admin: `/usuarios` is for anyone who administers some module (`is_any_module_admin`), who sets only the columns of the modules they administer (`admin_add_member`, `admin_set_module_role`, `admin_remove_member`; someone left `none` everywhere leaves the group); linking access ↔ associate is for the Associados admin. SQL checks: `can_read_finance`/`can_write_finance`/`can_edit_group` (editor), `can_read_associates`/`can_write_associates`/`can_manage_associates`, `can_read_inventory`/`can_edit_inventory` (contributor)/`can_manage_inventory` (editor).
- Session: `lib/server/session.ts` is the only file that reads `memberships`. `Member` has `db`, `user { id, email }`, `associateId`, `managesUsers` and `finance`/`inventory`/`associates` as `ModulePermissions { role, canRead, canWrite (contributor+), canReview (editor+), canAdmin }`; `moduleAccess(member)` says which modules show (menu, `Brand`), `requireModule` in the `/financeiro`, `/inventario` and `/associados` layouts sends people without access back to Início; guards `pageSession`, `pageMember`, `memberOrError`, `financeReaderOrError`, `associatesReaderOrError` (export, attachment and report routes), `<module>WriterOrError` (contributor+), `<module>EditorOrError` (editor+), `usersAdminOrError`, `requireFinanceEditor`/`requireFinanceWriter`, `requireAssociatesEditor`/`requireAssociatesWriter`, `requireUsersAdmin`. Module headers take `member` (`AppHeader member={member}`).

## gestao › financeiro

- Login with Google (OIDC, PKCE, `state`, `nonce`; `/auth/google` → `/auth/callback`) for any e-mail a module admin registered in `/usuarios` (`auth.users`, any domain, `email_verified` required; the Google `sub` is bound on first login and cleared when the user leaves their last group). Sessions in `auth.sessions` (cookie `__Host-geas_session` holds a random token; only its sha-256 is stored; 30 days sliding). `/auth/e2e` (test login) works only with `E2E_LOGIN=1` on `next dev`. Roles in `000_roles.sql`, `auth` schema in `001_schema.sql` (`geas_app` login role is NOINHERIT and only switches to `authenticated`/`geas_auth`). RLS per group.
- Money stored as integer cents (`lib/money.ts`).
- Migrations in `db/migrations/`: `000_roles.sql` (cluster roles) and `001_schema.sql` (baseline consolidated on 2026-11-21 from the 56 dev migrations; their history is in git). New changes go in `002_…` onward (applied by `scripts/db.mjs`, tracked in `geas_meta.migrations`); while nothing is in production `001` may still be edited (`npm run infra:reset`). Numbers in parentheses in this file (e.g. "(049)", "036") are tags of the pre-baseline history. Infra and Azure notes in `apps/gestao/db/README.md`.
- Model (glossary in `apps/gestao/docs/modelo.md`): `ledger_entries` = entry (date, `name` shown as "Histórico", account, payment method, `document_filed`, total); `entry_splits` = per-category split with description and optional associate; `statement_lines` = imported OFX lines (`external_id` = FITID, "ID OFX"), linked to entries via `reconciliation_links`. `categories.code` is derived from `parent_id` + `position` by `renumber_categories` (036): never write or hard-code it (except roots `1`/`2`); reference rubricas by id. The Rubricas screen is a client draft (`lib/category-draft.ts`) saved in one call to `save_category_tree`. `categories.ledger_code` / `accounts.ledger_code` = accounting chart code (domain `ledger_code`, mask `0.0.0.0.0000`, mirrored in `lib/ledger-code.ts`).
- All writes go through audited SQL functions (no direct write policies on catalogs, accounts, entries or statement tables). List views read `ledger_entry_rows` / `entry_split_rows` (security_invoker, with `external_ids` and `search_text`).
- Paths below under `lib/` are in `lib/finance/` unless they are the shared ones listed in the gestao section.
- Column chooser (Movimentações and Detalhamento, like Materiais): "Colunas" menu in the filter row (`components/finance/entries/columns.tsx`, `EntryColumnsProvider`); Data, Histórico and Valor are fixed; hidden ids per view in cookie `fin_<view>_colunas` (path /financeiro), read on the server (`hiddenEntryColumns` in `lib/finance/entry-columns.ts`), toggled client-side without reload; the tables are `table-fixed`: short columns have px widths, text columns (Histórico, Associado, Descrição) share the measured container width (`useTableWidth`, the container, never the table, or widths feed back) as a minimum each plus the rest split by typical text length (p90 of loaded rows), so hiding columns lets text show in full; `useVisibleColumns` is memoized so virtualized rows stay memoized; filters on hidden columns still apply (chip stays); phone cards and exports unaffected.
- Bulk actions (Financeiro Administrador only since 015: `can_admin_finance`, `financeAdminOrError`, `canBulk` in `EntryListProvider`; the Editor reviews one entry at a time and imports only OFX statements; `components/finance/entries/bulk-account-bar.tsx`, selection in `EntryListProvider` keyed by entry id in Movimentações and split id in Detalhamento, cleared when the list query changes; shown at once via `override`): Movimentações = move account (`move_ledger_entries_account`), payment method (`set_entries_payment_method`), documents filed/pending (`set_entries_document_filed`), mark reviewed (`review_ledger_entries`); Detalhamento = split category (`set_splits_category`, sign must fit the kind; fee-linked splits only to fee categories) and associate (`set_splits_associate`; refused for fee-linked splits and entries paying debts). 012 functions update splits in place (fee links kept, unlike `update_ledger_entry`), max 500, audit `ledger_entry.updated` with before/after snapshots and `reason: em lote` (history shows "em lote"). Deliberately not bulk: date, value, Histórico, delete. Detalhamento also groups/ungroups (014): `merge_ledger_entries(group, split_ids, p_entry)` (entries of the marked splits → one, with date/histórico/conta/forma/documento/pasta/observação filled in a form (`MergeDialog`, prefilled from the first marked split's entry, "Copiar dados de" any involved entry); the row kept is the first marked split's entry; none reconciled, no attachment on the ones that go; split ids kept so fee links stay; debt payments summed; audit `ledger_entry.merged` + `ledger_entry.updated` reason `agrupado`) and `split_ledger_entry_splits` (each marked split → own entry copying the original's fields; refuses reconciled or debt-paying entries); after either, the client list refetches page 0 (`reloadList`/`listVersion` in `EntryListProvider`). pgTAP `finance_merge.test.sql`, `finance_import.test.sql`. pgTAP `db/tests/finance_bulk.test.sql`.
- Lojinha (019): an income (receita) rubrica marked "venda de itens" (`categories.sells_items`, inherited by children: `category_sells_items` / `categorySellsItems` in `lib/finance/sales.ts`; toggled in the Rubricas draft menu) gives each split an "Itens vendidos" section (`components/finance/entries/sale-items.tsx`: material à venda, quantity, unit price prefilled from `inventory_materials.sale_price_cents`; with items the split value is their sum). Items ride in `p_splits[].items` to `create/update_ledger_entry` (`write_entry_splits` validates them into `entry_sale_items`); `sync_entry_sales` then writes off (reason `venda`, soonest expiry first, channel `financeiro`, `para_revisar` unless the user is Inventário Editor) or returns the difference to the same lots (`entry_sale_draws`); `delete_ledger_entry` returns everything. Triggers refuse moving item splits to another entry or to a rubrica that doesn't sell, and deleting an entry with draws outside `delete_ledger_entry`. Catalog `finance_sale_materials` (readable by finance readers without inventory access). pgTAP `finance_sales.test.sql`, e2e `lojinha.e2e.ts`.
- Statement import is OFX-only; the CSV statement import code was removed for good (`lib/csv-reader.ts` is only the generic reader used by `/importar`). Exports: column definitions in `lib/export/columns.ts`, rendered as XLSX or CSV; accounting CSV at `/financeiro/exportar/contabil` (see `docs/contabilidade.md`).
- SQL tests: `db/tests/*.sql`, run inside a rolled-back transaction (see each file's header); pgTAP lives in schema `extensions`, only in the local/CI database.
- Routes: module = 1st segment, menu item = 2nd, header tab = 3rd (`/financeiro/lancamentos/movimentacoes|detalhamento|realizado`, `/financeiro/extrato/conciliar|importar`, `/financeiro/mensalidades/controle|devedores`, `/financeiro/configuracoes/<aba>`; associates, sections and the associates CSV import live in `/associados`, and `/financeiro/configuracoes/associados` redirects there); query string only for filters and display modes. Area roots redirect to the first tab; the module root `/financeiro` is the finance Resumo (year totals, account balances today, month by month, recent entries, overdue fees) and the menu starts with "Resumo". Every finance page header gets "Financeiro" after Início in the breadcrumbs (wrapper `PageHeader` in `components/finance/nav/page-header.tsx`). Movimentações and Detalhamento share `app/(financeiro)/financeiro/lancamentos/entries-screen.tsx`; `voltar` carries the list path + filters (`listHref` in `lib/entries.ts`). The `rubrica` filter is compact (`id` = subtree, `-id` = excluded subtree; `encodeCategorySelection`).
- Screens: every page header uses `PageHeader` (`components/finance/nav/page-header.tsx`: title, `SectionTabs` beside it, actions on the right, description, filter rows as children) inside `PageBody`/`PAGE_BODY`; never hand-roll an `<h1>` row. - Attachments (receipts, 027; Azure Blob container `comprovantes`, browser uploads/downloads with short SAS URLs issued only after `can_write/read/delete_attachment_object`, size and type read from the blob by the server; Azurite locally) are switched off by a feature toggle: `ATTACHMENTS_ENABLED` in `lib/features.ts` (`NEXT_PUBLIC_FEATURE_ATTACHMENTS=on` turns them on, read at build time). ## gestao › inventario

- Model and vocabulary in `apps/gestao/docs/inventario/modelo.md` (material by unit with tag `GEAS-000-0000` or by lot; divisions as a tree; families with 3-digit code; movements with review status). Schema in `db/migrations/001_schema.sql` (`inventory_*`); pgTAP in `db/tests/inventory.test.sql`; e2e in `e2e/inventory.e2e.ts` (manager, chief, viewer).
- Roles: the shared levels (gestao › Roles); Colaborador (the chefe) movements start `para_revisar`, Editor reviews and keeps divisions/families. Set in the shared `/usuarios`.

- Routes: `/inventario` redirects to `/inventario/materiais` (no inventory Resumo; what needs attention is on the Gestão Início `/`; the menu starts with Materiais; managers see an "N para revisar" pill in the Materiais header), `/inventario/materiais` (list by location: "Todos" (default, every location plus materials without stock) then one tab per root division, subdivisions as group rows; columns Estado (worst condition, `ConditionPill`), quantity, counts of the two previous years, validity, unit value range, total value, chosen by the user (cookie `inv_materiais_colunas`); sort by any column inside each division; Estado, Quantidade (also vs. minimum), Validade (expired / not expired / none) and Valor unitário have a column menu (sort + filter by values/range, `components/inventory/materials/column-menu.tsx`; shared header bits (`HeadIcons`, `HEAD_TRIGGER`) in `components/shell/column-head.tsx`, outside the "use client" module, also used by the finance entry tables); filters and sort in the query (`lib/inventory/material-list.ts`); search `q` matches `inventory_material_rows.search_text` (043: name, description, family, lot notes/supplier, unit tag/code/description/notes; unaccented lowercase via `inventory_search_normalize`, mirrored in `lib/inventory/search.ts`), every word must match; `/novo`, `/[id]`, `/[id]/editar` carry `voltar` back to the list with its filters), `/inventario/movimentacoes`; Configurações (gear) with tabs `/inventario/configuracoes/divisoes|familias` (`components/inventory/settings-tabs.tsx`). Read errors show `app/(inventario)/inventario/error.tsx`.
- Review (044): `review_status` is `para_revisar` | `revisado`. Colaborador (chefe) movements and every movement from the quick screens start `para_revisar`, even an Editor's; Editors review (also their own) via `inventory_review_movements` (Movimentações › Para revisar, bulk with optional note; or per row in the material history; `components/inventory/review.tsx`). ## Shared UI (`packages/ui`, `@geas/ui`)

- Same identity in every internal app: build screens from `@geas/ui`, never hand-rolled CSS classes or app-local copies of primitives.
- `@geas/ui` (root export): app shell — `UserMenu` (email, role, `adminLinks` under "Administração", Sair; every gestao header uses `AccountMenu`), `AppBrand` (module switcher: `current` is `gestao | financeiro | inventario | associados`, any number of modules, logo goes to `homeHref`), `AppLogin`/`AppLoginForm`, `AppHeader`, `UserMenu`, `PageHeader`, `PageBody`, `SectionTabs` (pill buttons; below `sm` a menu button with the active tab, `components/section-tabs-menu`); `AppHeader` shows a menu button (`components/app-nav-menu`) below 1024px; `utilities` are `{ href, label, icon, active }`.
- `@geas/ui/components/<name>`: shadcn/ui (`base-mira`, Base UI primitives — not Radix) plus `section-card`, `stat-card` (`StatCard`, `ListCard`), `option-controls` (`OptionSelect`, `OptionCombobox`) and `tree-drag` (`useTreeDrag`, `DragHandle`: drag rows of a tree table before/after/inside; used by Rubricas and Divisões). Reorder only by dragging: no up/down arrows. Add shadcn components with `npx shadcn@latest add <name>` inside `packages/ui`. Imports inside the package use `@geas/ui/...` (self-reference), never `@/`.
- Links: always `import { Link } from "@geas/ui/components/link"` (`next/link` with `prefetch={false}` by default; ESLint blocks `next/link`): pages are dynamic without `loading.tsx`, so prefetch only multiplied requests (one per visible link). Never cache pages or group data in shared/HTTP caches. Logo and icons are imported files (`packages/ui/src/assets`, `apps/gestao/assets/images`), never `/images/...` URLs: hashed name, 1 year immutable. A client never calls `router.refresh()` after a Server Action that calls `revalidatePath` (the action response already brings the new screen); only for client-only changes such as a cookie. `instrumentation.ts` + `lib/server/response-compression.ts` coalesce Next's per-chunk gzip flush (navigations were 7x bigger): check sizes when upgrading Next.
- `@geas/ui/lib/utils` (`cn`) and `@geas/ui/lib/use-action-toast` (Server Action result → toast).
- `@geas/ui/lib/text`: `displayCase` (all-caps names → "José da Silva", pt particles lowercase); `PageHeader` applies it to every string breadcrumb.
- Forms with typed fields use `ActionForm` (`@geas/ui/components/action-form`), never `<form action={…}>`: React 19 resets uncontrolled fields after every action, even on error. `ActionForm` submits via `onSubmit` + transition and clears only when `result` (the `useActionState` state) has no `error`. Plain `<form action>` only for hidden-field forms (toggle, remove).
- Cards: every card surface (SectionCard, StatCard, ListCard, hand-made panels) uses the `surface` utility from `theme.css` (soft 1px border, card background); never hand-roll `rounded-lg border bg-card` or dark borders. Inner dividers stay `border-b`. `html` reserves the scrollbar gutter (no layout jump). Choice between a few options with explanations: `radio-group` as choice cards (`FieldLabel` > `Field orientation="horizontal"` > `FieldContent` + `RadioGroupItem`), side by side from `sm`, stacked below; e.g. Controle in the material form. In two-column form grids use `items-start` so a help text under one field does not push the label of its neighbour.
- Users: `@geas/ui/lib/roles` (the five module levels, `ROLE_MODULES`, `GroupUser`) and `@geas/ui/components/users-manager` (one role column per module; only the caller's modules are editable, `adminOf`). - Theme: each app's `app/globals.css` starts with `@import "@geas/ui/theme.css"` (Tailwind, tokens, shell CSS in `@layer components`, legacy CSS in `@layer legacy` below utilities) and the root `<html>` carries `data-app="gestao" | "financeiro" | "inventario" | "associados"` (in gestao, set by each module root layout), which sets the accent (`--app` → `primary`/`accent`: purple / dark orange / green `#0b7a4b`).
